# AHCソルバの実行と結果確認

適用中のコンテストルールと `AGENTS.md` に従い、依頼された実装の検証または指定された実験を行う。skillの利用は、実験範囲やソルバ変更の許可を広げない。

## 実行条件

- `pahcer_config.toml` と `single.py` で入力・出力・ビルド手順を確認する。テンプレートの変数が未展開なら実行しない。
- 入力はリポジトリ相対の `pahcer/in/`。設定のseed範囲は `[start_seed, end_seed)` で、終了seedを含まない。指定された範囲と設定が異なる場合は、その条件を反映した一時設定を作り `--setting-file` で渡す。
- スコア比較・探索の候補、範囲、評価基準はユーザーの指定に従う。不足する解法上の判断を補わず質問する。新ルール適用中は候補や推奨案を提示しない。
- 必要な入力と `tester` / `vis` の存在を確認する。配布ツールが未ビルドなら報告して止める。
- ビルドと実行でファイルが更新される。`out.txt`・`err.txt`・seedごとの出力は上書きされるため、比較や再現に必要な既存結果は実行前に別名で保存する。

## 複数ケース：JSON出力を優先

まず `pahcer --version` と `pahcer run --help` で利用可能なオプションを確認する。基本コマンドは次のとおり。

```sh
pahcer run --json -c "変更内容または実験条件"
```

機械処理のために保存する場合は、実行ごとに異なるパスへ標準出力・標準エラーを分けて保存する。パイプを使う場合もpahcer自身の終了コードを確認する。

pahcer 0.4.0のJSONモードでは、ケースごとに1行のJSONが出力され、最後の集計表示は出ない。出力順はseed順とは限らないため、`seed` で対応付ける。標準出力全体を単一のJSONとして読まない。ビルド等の非JSON出力が混ざった場合は区別して保持し、不明な行を黙って捨てて成功扱いしない。

| フィールド | 意味 |
| --- | --- |
| `progress` | 完了したケース数 |
| `seed` | 入力ケースのseed |
| `score` | 生スコア。失敗時も0になるため、これだけで成否を判断しない |
| `relative_score` | 相対スコア。`--rank` 使用時は同名のまま順位スコアになる |
| `execution_time` | 実行時間（秒） |
| `error_message` | 成功時は空文字。失敗時の詳細 |

終了コードに加え、予定seedとの一致・重複や欠落・各ケースの `error_message` を確認する。中断や欠落を全ケース完了として扱わない。

標準設定では、完了後の集計結果は `pahcer/json/result_*.json` に保存される。実行前後のファイル一覧と実行時刻・コメントを使い、今回のファイルを特定する。このファイルは単一のJSONで、`case_count`、`total_score`、`max_execution_time`、`wa_seeds`、`cases` などを含む。出力先は設定の `test.out_dir` を確認する。

- 履歴を一覧する場合は `pahcer list`、ケースごとの比較・集計には保存されたJSONを使う。
- 比較は同じseed集合・評価基準・実行条件で行う。相対スコアはローカルのベストスコア、順位スコアは保存された履歴に依存するので、基準が変わった値を単純比較しない。
- 固定したベストスコアで評価する指定がある場合は `--freeze-best-scores` を使う。`--rank`、`--shuffle` など実験条件を変えるオプションは依頼に合わせて選ぶ。
- 通常は結果ファイルを残す。`--no-result-file` は結果保存を省く指定がある場合だけ使う。`--no-compile` は対象コードに対応するビルド済みバイナリだと確認できる場合だけ使う。

## 単一ケースの再現

```sh
uv run single.py -s <SEED>
```

標準出力のスコア、`out.txt`、`err.txt` を確認する。`vis.html` の生成有無は配布visualizerに依存する。対話型ではtesterの終了状況・ログも確認し、ラッパースクリプトの正常終了だけで成功と判断しない。パスや挙動は問題ごとの `single.py` を正とする。

権限エラーや `Invalid cross-device link` が出た場合は、エラー箇所とビルド出力先を確認する。必要な場合だけ実行環境の承認手順に従って再実行し、無条件にサンドボックス外で実行しない。

## 報告

コマンド、コードの版・変更状態、設定とseed範囲、完了数・失敗seed、指定された指標、実行時間、比較対象、結果ファイルの場所を簡潔に示す。失敗時は該当ログと再現コマンドを添える。

結果の機械的な集計と実装上の不一致の調査に留める。新ルール適用中はスコアから解法自体の問題点・改善方針を考察しない。指定済みの候補・範囲・評価基準に基づく機械的な選択は可能だが、結果をソルバへ反映する作業まで依頼されているか確認する。
